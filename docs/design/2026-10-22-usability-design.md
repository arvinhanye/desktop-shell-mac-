## 1. 目标与范围

让已有功能无需手改 JSON 就能日常使用，减少应用栏的空白占位，并让启动失败有明确反馈。

本次交付限定为：

1. 编辑项目显示名称、默认打开应用、提醒事项列表，调整显示顺序。
2. 应用栏随内容收缩；提供“标准”“工作优先”两个布局预设及八个展示组件的显隐设置。
3. 应用启动中的防重复操作、失败提示与恢复。

不加入项目工作台、进度便签、专注计时、天气、音乐控制、快捷指令、应用发现或应用增删管理。不改变项目目录、磁盘文件或系统设置，不创建、删除或移动提醒事项列表。

## 2. 已核对的现状

- `web/widgets/launcher.css`：启动栏固定跨两列；当前两枚应用图标仍占整块宽底板。
- `web/widgets/launcher.js`：项目关联仅控制高亮，点击调用 `launchApp`；失败只由 Bridge 记日志。
- `web/widgets/projects.js`：`apps` 中首个有效应用决定项目打开按钮，整个数组还用于启动栏高亮。
- `Sources/DesktopShell/TodoItems.swift`：旧配置通过提醒列表名称匹配；多个项目共享列表时由原始项目数组里第一个项目认领。
- `Sources/DesktopShell/UiStateStore.swift`：已有原子文件保存、旧字段默认值；外观更新已有失败回滚及多页面推送。
- `web/widgets/clock.js`：时钟不仅展示日期，还维护全局时间与时段；隐藏展示不等于停止这项服务。

## 3. 项目编辑

### 3.1 界面与交互

- 项目卡标题区增加“管理”按钮。开启后，在项目行显示编辑、上移、下移和原有移除操作；退出管理后恢复日常打开项目的布局。
- 上移、下移每次移动一位，立即保存；首尾对应按钮禁用。保存期间禁用重复排序请求，失败保留之前的顺序并在卡片提示。
- 编辑在同一个网页中打开面板，包含“显示名称”“默认打开应用”“提醒事项列表”“取消”“保存”。不展示或编辑路径。
- 名称去首尾空白，长度为 1–100 个 Swift Character；网页按 Unicode 字素计数。只改显示名，项目 ID、目录、标签保持原样。
- 默认应用仅从现有 `config.apps` 选择。选中的应用移到该项目 `apps` 首位，其余关联按原序保留；第一版不增加“清空全部应用关联”操作。
- 提醒列表可保持当前绑定、选择可写列表，或明确选择“不关联”。未授权时仍可改名、改应用、排序、解除关联；新增绑定需已有读取权限。
- 名称及列表标题使用 `textContent`。选择项使用页面内按钮列表，沿用现有点击与文本框焦点机制，不增加全局快捷键。
- 取消或关闭丢弃未保存的表单；保存失败保留草稿。项目被另一页面移除时关闭失效编辑器并提示。
- 编辑面板与外观/布局面板互斥，避免相互遮挡。多屏的未保存草稿各自独立；保存结果统一广播。

### 3.2 保存与兼容

新增可选配置字段：

- 顶层 `projectOrder: [String]?`：仅决定公开项目列表的显示顺序，原始 `projects` 数组顺序保持。缺字段时沿用原序；读取时忽略重复或已不存在的排序 ID，未列出的项目按原序补到末尾。新增项目显示在末尾，移除项目时清理其排序 ID。
- 项目 `remindersListId: String?`：保存原生 EventKit 列表标识。存在时仅按 ID 查找；缺失时继续使用旧 `remindersList` 名称规则。纯加载不迁移、不重写配置。

选择新的列表后保存 `remindersListId`，清除旧名称绑定；解除关联时同时清除两个字段。仅改名称、应用或排序时，原有绑定字段不动。

EventKit 标识不是永久身份：全量同步等情况可能更换标识。ID 失联时保留配置、明确提示重新选择，绝不按同名列表自动改绑。

新绑定禁止选择已被其他项目占用的列表。历史共享绑定保留原先归属，不因界面排序改变；可在编辑器中明确解除或改选。

对显式 ID 绑定，列表失联或变为只读后，向该项目新增待办返回错误，不静默写进默认列表。旧名称配置继续兼容原有处理。未关联的项目仍使用系统默认列表。

写操作读取最新未过滤配置，保留不在当前展示列表中的项目、应用和字段；只修改本次请求指定的字段。保存成功后更新内存、广播 `config`，重新计算待办归属；失败不广播成功状态。排序请求与最新可见项目集合不一致时拒绝，并要求前端刷新。

### 3.3 新增的受限 Bridge 合约

这些是本方案提出的新增接口，不是现有白名单已经具备的能力。仍只接受 `shell://app` 主框架，拒绝未知参数，每条请求回复一次。

| action | 参数 | 作用 |
|---|---|---|
| `getProjectEditOptions` | `projectId` | 读取当前编辑值、提醒权限、可选列表、关联状态 |
| `updateProject` | `projectId`, `name?`, `appId?`, `reminderListOptionId?` | 缺省字段不动；列表选项为 `null` 表示解除；至少含一项变更 |
| `reorderProjects` | `projectIds` | 最新可见项目 ID 的完整、不重复排列，只改变显示排序 |

列表选项包括页面内选项 ID、标题、来源显示标签、只读/已被占用标志。相同标题通过来源及选项序号消歧；选择和写入按标识，不按标题。来源只包含供用户区分列表的显示名称，不返回账户凭据或账户标识。

选项 ID 由 Swift 分配，符合既有 ID 字符规则；Swift 在进程内维护其与原生列表标识的对应，不把 EventKit 对标识格式的约定强加给通用 Bridge 校验。每次打开编辑器刷新选项，保存时重新校验权限、列表存在性、可写性和占用情况；陈旧选项返回错误。

`getConfig` 和 `config` 推送继续隐藏项目路径、应用 bundle ID、提醒列表名称和原生列表 ID。仅上述编辑接口公开选择列表所需的最小显示信息；日志仍只记录动作、ID、数量和错误码。

## 4. 应用栏与布局

### 4.1 应用栏自适应

- 应用栏始终锚定安全区域左下，宽度等于可见图标组所需宽度与原有水平内边距之和，上限为现有双列宽度和实际可用宽度中的较小值。
- 两枚应用时只占实际所需空间；不拉大图标填空。保留现有图标尺寸、底图、圆角、边框与高度。
- 应用很多时使用单行水平滚动，图标项不收缩、不越界；名称单行省略并保留完整可访问名称。
- 应用为空时隐藏应用栏底板，不保留空点击区和空毛玻璃；恢复有应用时按显隐设置显示。
- 不增加应用管理、自动发现、自动推荐或改变图标点击含义；点击继续启动应用。

### 4.2 两个预设与组件显隐

- **标准**：保持现有双列位置。
- **工作优先**：交换两列内容，使项目、待办位于左列，时钟、角色卡、系统状态位于右列，问候语随所属列交换。应用栏仍留在安全区域左下，律动位置保持。
- 两个预设不改组件内部样式，也不触发动画切场；仅切换位置 token。全部新增尺寸、颜色、间距、时长仍集中在 tokens。
- 显隐列表覆盖时钟、问候语、项目、应用栏、待办、系统状态、角色卡、律动。切换预设不覆盖独立的显隐选择。
- 隐藏的卡片位置留作壁纸留白；第一版不做自动重排、任意拖拽或缩放。
- 布局入口放在原生菜单“桌面布局…”，打开同网页面板：优先鼠标所在屏幕，否则主屏幕。只打开面板，不自动聚焦输入框或激活应用。即使全部组件隐藏，也保留恢复入口。
- 面板提供“恢复布局默认”，只恢复标准布局和全部展示，不修改头像、背景、语音开关、桌面文件显隐。

### 4.3 持久化与运行边界

`ui.json` 新增 `layoutPreset`（`standard` / `work-first`，缺省 `standard`）和 `widgetVisibility`（八个展示组件 ID 对应的布尔字典，缺省全部为 `true`）。旧文件正常读取；文件中的未知预设回落标准、未知组件被忽略、缺失或非法单项采用显示默认值，不连带丢弃已有外观设置；Bridge 输入非法值仍整条拒绝。

扩展 `saveUiState`、其回复及 `uiState` 推送，保存完整规范化状态；支持只更新布局字段而不触碰外观字段。`widgetVisibility` 请求按单个组件做局部补丁，例如 `{projects: false}`，由 Swift 基于最新状态合并，避免多屏设置相互覆盖；回复和事件返回完整显隐字典。沿用原子保存、失败回滚和向全部页面推送。连续点击保存串行化，失败不展示伪成功。

菜单触发新增瞬时事件 `openLayout`；它仅控制目标页面的面板打开状态，不落盘。页面尚未就绪时保留一次打开意图，加载成功后交付；重新加载不会反复自动弹出。

- 展示组件隐藏使用宿主显隐，不简单卸载时钟和共享时间服务。
- 隐藏律动时停止该组件的绘制；页面不可见时亦停止绘制，恢复可见后使用最新状态，不引入轮询。
- 隐藏律动不在本次顺带重写原有系统音频捕获策略；仍遵守已有暂停和播放检测规则。
- 隐藏有输入焦点的组件或关闭面板时先释放焦点，再移除点击区域，避免键盘留在不可见输入框。
- 预设变化、显隐、窗口尺寸及安全区域变化后，显式调度 hit/drop/glass 三类区域上报；不依赖目前未监听的 `data-layout` 属性自动触发。
- 隐藏项目卡后清空当前页面的项目选择、移除拖入区域，待办恢复显示全部，避免按一个不可见的项目过滤。显示状态变化也更新毛玻璃，保留 Finder 的空白点击穿透。页面恢复可见时重新测量并上报三类区域。

## 5. 应用启动反馈

- 每个应用按 ID 防止在途重复启动，其他应用按钮仍可使用。
- 启动成功维持原名称，不追加多余成功提示。
- `not-found`：名称行临时显示“未找到应用”，完整说明为“未找到此应用，请检查安装或配置”。不将所有失败推断为未安装。
- 其他错误：名称行临时显示“启动失败”，完整说明为“启动失败，请稍后重试”。
- 提示持续 3 秒，复用名称行及 danger token，不改变卡片几何。完整说明放在可访问描述和悬停提示，保留原应用名称作为可访问名称。
- 每次请求和提示计时有独立版本，防止旧回复、旧计时器覆盖新配置或新提示。组件销毁时清理；失败消耗 Promise 拒绝，由 Bridge 统一记录日志。

## 6. 验收原则

实现阶段逐项采用 RED → GREEN，并记录每个独立任务的交付结果；子代理复核只作为自查，不替代项目规定的正式独立审查。

自动化至少覆盖：

- 旧配置和旧 ui.json 兼容；新增字段保存往返；保存失败不丢旧内容。
- 项目改名不改 ID/目录；默认应用移首保留关联；显示排序不改变历史共享列表归属。
- 列表同名、改名、失联、只读、撤权、选项过期、另一屏幕删除项目、异步旧查询返回。
- 公共配置投影保持脱敏；新增接口未知键、非法值、来源检查与回复次数。
- 零/二/多应用宽度与溢出；显隐和两预设正确；三类区域随之更新。
- 隐藏时钟仍更新时间；隐藏或不可见的律动不绘制；焦点释放与全部隐藏后的恢复入口。
- 启动成功、not-found、其他失败、重复点击、旧回复和旧计时器、销毁后回复。
- Swift 与网页 mock 合约一致，重载和多屏推送保持一致。

使用项目现有 `scripts/test.sh`、`scripts/test-web.sh`、`swift build`、`git diff --check`；实现结束后构建签名应用，验证包与签名。素材处理脚本若保持不变，无需重复素材转码。

真实桌面另行验收：中文输入和标准编辑快捷键、面板不抢其他应用键盘、列表选择、两布局目测、图标区避让、横向滚动、Finder 点击穿透、项目拖入、全部隐藏后恢复、多显示器一致性以及重启持久化。浏览器 mock 或单元测试不计作这些项目通过。

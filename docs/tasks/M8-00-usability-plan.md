## 分支与交付约定（本批计划需确认的流程补充）

五项存在源码依赖。为连续实现且不提前合并 main，本批采用**串行接续分支**：首项 `task/M8-01` 从执行时核实的最新 main 创建，后续 `task/M8-02` 到 `task/M8-05` 从前一项完成自查的本地提交创建。一次只实现一项；每项记录准确起点 SHA、范围 diff、验证和后继分支。

这是本批对“每项都从 main 创建”的有限流程调整，随本计划一起审阅；不改长期规则。单项范围检查以记录的起点 SHA 为基线，最终累计差异另与 main 核对。每项通过后仅做本地提交，提交信息遵守 `M8-xx: 简述`；不自行合并 main、不推送。正式审查者后续决定逐项或整批集成。

初次建分支前核对远端和现有 worktree，保留现有方案/任务文件。读取远端失败则明确记录，避免声称本地 main 就是远端最新。分支准备遵守 `using-git-worktrees`，优先复用适合当前任务的检出，不启动临时应用的开机自启。

## Review Focus

1. 手写的旧配置、不可见配置项及扩展 JSON 键不得因编辑单个项目丢失 → M8-01 的配置保持测试。
2. 旧共享提醒列表不能因显示排序而改变归属，ID 失联不能写到默认列表 → M8-01 的映射及路由测试。
3. 另一屏幕修改配置、隐藏组件或迟到异步响应不能覆盖新状态 → M8-02 / M8-03 / M8-04 的并发与生命周期测试。
4. 全部隐藏后有恢复入口；隐藏时钟继续提供时间，隐藏输入先还焦点 → M8-03 / M8-04 的瞬时事件及显隐测试。
5. 失败提示不能被旧请求/旧计时器清除，不能把配置缺失断言成未安装 → M8-05 的 generation 和错误文案测试。

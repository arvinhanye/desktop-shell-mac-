## 目标

应用捕获系统正在播放的声音，算出频谱推给网页，桌面上的律动条跟着音乐跳。暂停时把整套捕获拆掉；静音 2 秒后不再推送。这一步只要没暂停就一直捕获，"没有应用在放声音时不开捕获"留到 M5.5-03。

  - "技术探针"的系统音频捕获探针，下面第 1 节照它做。
  - "省电要求"：暂停时停止捕获，要停掉 IOProc，而不只是停止推送。

  - "联动规则"表的 `paused` 一行。
  - "开发方式"：需要系统权限的功能只能用签名的 `.app` 测试。
- **已经就位的部分**：
  - `Info.plist` 已经有 `NSAudioCaptureUsageDescription`（M2.5-01）。
  - 固定的自签名证书已经配好。第一次启动会弹一次"系统录音"权限框，之后不再弹。

### 1. 捕获（新建 `Sources/DesktopShell/AudioSpectrum.swift`）

```swift
@MainActor
final class AudioSpectrum {
    var onSpectrum: (([Double]) -> Void)?   // 在主线程回调
    func setPaused(_ paused: Bool)           // 初始按暂停处理：第一次收到 false 之前不开捕获
    func stop()                              // 退出时调用，尽量同步拆完
}
```

**搭建**（照探针）：

1. 创建 tap：`CATapDescription(stereoGlobalTapButExcludeProcesses: [])`，`muteBehavior = .unmuted`，`isPrivate = true`，然后调用 `AudioHardwareCreateProcessTap`。
2. 读 tap 的 `kAudioTapPropertyFormat`（采样率、声道数、是否交错），按它创建 `SpectrumAnalyzer`。不要假设一定是 48 kHz。
3. 创建私有聚合设备：
   - `kAudioAggregateDeviceIsPrivateKey = true`。
   - 主子设备和子设备列表都是当前的默认输出设备。
   - tap 列表是上面那个 tap。
   - `kAudioAggregateDeviceTapAutoStartKey = true`。
   - 调用 `AudioHardwareCreateAggregateDevice`。
4. 调用 `AudioDeviceCreateIOProcIDWithBlock`，传一个专用的串行队列（不能是主线程），然后 `AudioDeviceStart`。

**拆除顺序**（探针验证过，没有残留）：`AudioDeviceStop` → `AudioDeviceDestroyIOProcID` → `AudioHardwareDestroyAggregateDevice` → `AudioHardwareDestroyProcessTap`。搭建中途失败时，把已经建好的部分按同样的顺序拆掉。

**线程**：
- 搭建和拆除都放在一个后台串行队列里做。第一次启动时，`AudioDeviceCreateIOProcIDWithBlock` 会一直阻塞到用户点完权限框（探针实测 5 秒）。
- 主线程只发指令、收结果。
- 暂停连续快速切换时，按最后的状态收敛，不要搭到一半又重新进入。

**IOProc 回调**：
- 把输入缓冲交给 `SpectrumAnalyzer`。交错格式直接给。如果是非交错的多个缓冲，先合成交错再给，或者直接取平均当单声道给，二选一，在代码注释里写明。
- 有结果时，只把**最后一组**发到主线程，调用 `onSpectrum`。
- `isSilent` 变化时，也发到主线程记日志（见下面"日志"）。
- 回调里不写日志，不碰 AppKit。

**默认输出设备变化**（监听 `kAudioHardwarePropertyDefaultOutputDevice`，例如插拔耳机）：
- 正在捕获时，先拆掉再重新搭建。
- 暂停时什么都不做，恢复时自然会用新设备。

**失败处理**：
- 任何一步返回错误：记一行错误日志（步骤名和 OSStatus），拆掉已经建好的部分，不自动重试。
- 下次 `setPaused(false)` 或设备变化时再试一次。
- 没有授权时，tap 可能照样建得成功，但收到的全是静音。这种情况不用特别处理，分析器在静音时不产生结果。

**日志**（用 `Log.notice` / `Log.error`，不写任何音频内容，不要每帧或每次回调都写）：

```
DesktopShell audio: capture started rate=48000 channels=2
DesktopShell audio: capture stopped reason=paused        （还有 deviceChanged、quit、error）
DesktopShell audio: sound=true                           （分析器从"静音中"恢复时）
DesktopShell audio: sound=false                          （进入"静音中"时）
DesktopShell audio: <步骤> failed status=<OSStatus>
```

### 2. 推送（`BridgeProtocol.swift`、`AppDelegate.swift`）

- 新增 `PageEvent.audioSpectrum(_ bands: [Double]) -> [String: Any]`，返回 `["event": "audioSpectrum", "bands": bands]`。
- `AppDelegate`：
  - 创建 `AudioSpectrum`，在 `onSpectrum` 里调用 `manager.broadcast(PageEvent.audioSpectrum(bands))`。
  - 在现有的 `monitor.onPausedChanged` 里，同时调用 `audio.setPaused(paused)`。`PowerMonitor` 启动时会先回调一次当前状态。
  - 在 `applicationWillTerminate` 里调用 `audio.stop()`。
- `audioSpectrum` **不进** `PageEventCache`，保持现状：它本来就不在 `replayOrder` 里，用测试确认这一点。
- 不改 `PowerMonitor`、`PowerPolicy`。

### 3. 测试

- **`PageEventTests.swift`（修改）**：
  - `audioSpectrum` 只有 `event` 和 `bands` 两个键，`bands` 是 12 个数，能被 `JSONSerialization` 接受。
  - `PageEventCache` 不缓存 `audioSpectrum`：先 `remember` 一条 `audioSpectrum`，`replay` 里没有它。
- **`AudioSpectrumTests.swift`（新建）**：把"什么时候搭建、什么时候拆除"写成纯函数或小状态机（例如 `AudioCaptureState`），测试以下情况：
  - 初始状态不搭建。
  - 收到暂停 false → 搭建；收到暂停 true → 拆除。
  - 搭建好的时候设备变化 → 重建。
  - 暂停时设备变化 → 不动。
  - 搭建失败后不自动重试；下次暂停 false 时再试。
  - CoreAudio 的调用本身不测。

- [ ] 退出应用 → 日志 `audio: capture stopped reason=quit`；再打开时不再弹权限框
- [ ] （Claude Code 测）放音乐时 DesktopShell 和 `coreaudiod` 的 CPU；"暂停动画"以后 `coreaudiod` 回到和应用没开时接近的水平
